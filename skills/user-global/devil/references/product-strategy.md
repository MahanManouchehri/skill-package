# Product, UX, and Strategy Lens

Use this reference when the decision changes user behavior, adoption, accessibility, cost/value, staffing, or long-term commitments.

Re-check the user problem against the proposed mechanism. Identify the intended actors, success signal, opportunity cost, adoption assumptions, rollout path, and likely misuse. Challenge solutions that solve an imagined workflow, add friction without value, or hide irreversible user-facing commitments.

For UX, inspect only relevant paths: user feedback, failure/recovery, destructive actions, accessibility, mobile/responsive behavior, localization, trust, permissions, and supportability. Distinguish a genuine product risk from personal taste.

For strategy, test build vs buy, vendor lock-in, operational ownership, staffing, maintainability, and what becomes harder after success. Trace second-order effects only when they affect a decision:

```text
Decision → immediate benefit → new dependency or behavior → future constraint or maintenance burden
```

Ask both: “What happens if it fails?” and “What breaks if it succeeds extremely well?” A reasonable answer may be that the risk is accepted because the present value outweighs it; make that trade-off explicit.
