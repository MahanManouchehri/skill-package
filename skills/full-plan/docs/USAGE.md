# راهنمای استفاده

<div dir="rtl">

## زمان استفاده

این Skill را پیش از طراحی یا پیاده‌سازی فیچری اجرا کنید که به endpoint تازه، تغییر قرارداد API یا چند endpoint هماهنگ نیاز دارد. نمونه‌ها:

- طراحی جریان تیکتینگ و گفت‌وگوی پشتیبانی
- ساخت بورد تخصیص کاربر به پشتیبان
- طراحی جریان ثبت سفارش، پرداخت یا پیگیری وضعیت
- تغییر endpointهایی که request، response، مجوز یا status code آن‌ها تغییر می‌کند

## فعال‌سازی

Skill برای درخواست‌های روشنِ مربوط به طراحی یا اجرای فیچرهای APIمحور قابل انتخاب خودکار است. برای درخواست صریحِ طرح کامل، عبارت زیر را در ابتدای پیام بنویسید:

```text
/full-plan
```

همچنین می‌توانید از فراخوانی صریح Codex استفاده کنید:

```text
$full-plan
```

## روند کار

1. Agent فقط فایل‌ها و منابع مرتبط پروژه را بررسی می‌کند؛ از جمله routeها، controller یا service، اعتبارسنجی، serializer یا resource، مجوزها و مستندات API.
2. endpointهای موجود، endpointهای پیشنهادی و اطلاعات نیازمند تصمیم را از هم جدا می‌کند.
3. برای هر endpoint، ورودی، رفتار و پاسخ دقیق را ارائه می‌کند.
4. endpointها را به سناریوهای ترتیبیِ نقش‌های کاربری تبدیل می‌کند.
5. پس از تأیید صریح کاربر، پیاده‌سازی را بر اساس همان طرح آغاز می‌کند.

## نمونهٔ درخواست

```text
/full-plan

برای بخش پشتیبانی، پشتیبان باید بتواند کاربران بدون مسئول را در بورد ببیند،
یک کاربر را به خودش اختصاص دهد، گفت‌وگوی او را باز کند و پاسخ بدهد.
```

در پاسخ، Agent ابتدا شواهد پروژه را بررسی می‌کند، سپس endpointهای لازم و سناریوی اقدامات پشتیبان را می‌نویسد. نام مسیرها، فیلدها و status codeها نباید بدون شواهد پروژه قطعی اعلام شوند.

## پس از دریافت طرح

طرح فقط برای بررسی است. برای شروع پیاده‌سازی، کاربر باید آن را صریحاً تأیید کند. اگر یک endpoint یا تصمیم کسب‌وکاری نامشخص باشد، Agent باید آن را به‌عنوان «نیازمند تصمیم» اعلام کند، نه اینکه قرارداد فرضی بسازد.
