## هدف مشارکت

تغییرها باید Skill را برای طراحی شفاف‌تر و دقیق‌تر قراردادهای API مفیدتر کنند، بدون اینکه آن را به مجموعه‌ای از قواعد نامرتبط یا وابسته به یک پروژهٔ خاص تبدیل کنند.

## پیش از ایجاد تغییر

1. مسئله و نمونهٔ واقعی استفاده را مشخص کنید.
2. بررسی کنید که آیا راهنمای فعلی واقعاً برای آن مسئله ناکافی است.
3. فقط دستورالعمل یا مستندی را تغییر دهید که برای حل همان مسئله لازم است.
4. از افزودن نمونه‌های فرضی، الزام‌های عمومی بی‌دلیل و تکرار قواعد موجود پرهیز کنید.

## معیارهای تغییر پذیرفتنی

- `SKILL.md` باید frontmatter معتبر با `name` و `description` داشته باشد.
- متن فارسی باید طبیعی، دقیق و مناسب مستندات فنی باشد.
- مسیرها، کلیدهای JSON و اصطلاحات قراردادی در مثال‌ها باید مشخصاً نمونه باشند یا به شواهد واقعی ارجاع دهند.
- تغییر نباید به Agent اجازه دهد بدون تأیید کاربر، قرارداد API، migration یا دادهٔ پایدار را تغییر دهد.
- مستندات باید با رفتار واقعی Skill هماهنگ بمانند.

## بررسی محلی

پس از تغییر، این موارد را کنترل کنید:

```powershell
python path\to\quick_validate.py path\to\full-plan
git diff --check
```

اگر validator به وابستگی runtime نیاز دارد، حداقل frontmatter، نام پوشه، نبودن placeholder و هماهنگی لینک‌های مستندات را دستی بررسی کنید.

## Pull request

عنوان pull request باید هدف تغییر را روشن کند. در توضیح، مسئله، تغییر انجام‌شده و نتیجهٔ مورد انتظار را کوتاه بنویسید. تغییرهای نامرتبط را در یک pull request ادغام نکنید.
